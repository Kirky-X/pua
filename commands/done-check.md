启用 **PUA Done Check / 完成质量检查**。

先读取：

1. `skills/pua/references/methodology-ding.md`（如果用户提到钉味/置身钉外/老板体感/周报）

不要默认读取完整 `skills/pua/SKILL.md`；本命令是轻量完成检查入口。

输出必须区分：

- `claim`：用户或 agent 口头声称完成了什么；
- `evidence`：已经有的命令输出、日志、截图、测试、文件、可观察结果；
- `missing`：还缺哪个验收动作；
- `status`：`candidate` / `needs_check` / `done_with_evidence`。

## 声明类型 → 所需证据对照表

验收时按 claim 的类型查表——哪种声明配哪种证据，什么不算充分：

| 声明类型 | 充分证据 | 不算数的东西 |
|---------|---------|-------------|
| bug 修好了 | 复现原症状的命令现在通过（贴输出） | 「代码改了应该好了」；只跑过一次新测试 |
| 回归测试有效 | red-green 验证：写测试→跑过→还原修复→必须见红→恢复修复→再跑绿 | 测试只跑绿过一次（可能是有洞的空洞测试） |
| 功能完成 | 验证命令（build/test/curl）退出码 + 关键输出节选 | 「本地跑过了」却贴不出输出 |
| 子 agent 报告成功 | 亲自查 VCS diff 确认改动真实存在 | 子 agent 的转述本身（转述不是证据） |
| 性能改善了 | 优化前后同一基准的对比数字 | 单次体感、没有基线的「快了很多」 |
| 文档/配置生效 | 加载或执行该文档/配置的观察结果 | 文件写好了就算 |
| 任务无法完成 | 结构化失败报告（已验证事实/已排除可能/缩小范围/推荐下一步） | 一句「做不到」；无证据的环境甩锅 |

两条硬规则：

1. **子 agent 说成功 ≠ 证据**——必须亲自查 VCS diff 确认改动存在、且与声明一致。
2. **回归测试没见过红 ≠ 有效**——先让它对旧代码失败，再让它对新代码通过。

如果没有证据，不要说完成；输出下一条最小验证动作。
